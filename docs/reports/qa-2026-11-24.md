## 6. 差异与建议（按严重度排序）

### 中风险（应修）

**M1. 依赖上限缺失，SQLAlchemy 2.1.9 在开启外键时多表同事务写入失败**

- 位置：[requirements.txt:3](file:///D:/mydemos/community-correction/requirements.txt#L3)（`SQLAlchemy>=2.0` 无上限）；生产引擎开启外键 [database.py:43-50](file:///D:/mydemos/community-correction/app/db/database.py#L43-L50)。
- 复现（最小 Parent/Child，仅 SQLAlchemy 原语）：同一 `commit()` 先插子表，抛 `IntegrityError: FOREIGN KEY constraint failed`；`Base.metadata.sorted_tables` 顺序正确，但 flush 顺序错误。
- 影响：当前三模块不受影响（API 每次事务只写单表；seed 已逐表 `flush()`）。但 [db.md:167](file:///D:/mydemos/community-correction/docs/contracts/db.md#L167) 要求 `final_color != green` 与 `review_tickets` 同事务写入，一旦按「reviews + tickets 同次 flush」实现将直接失败。
- 建议：钉住 `SQLAlchemy>=2.0,<2.1`，或在依赖升级前统一逐表 `flush()`，并为「reviews + ticket 同事务」补开外键的集成测试。
- 性质：环境/依赖问题，非 `app/db` 代码缺陷，但会阻塞下一模块。

**M2. 测试库未开启外键，外键/唯一语义无自动化覆盖**

- 位置：[tests/test_db/conftest.py](file:///D:/mydemos/community-correction/tests/test_db/conftest.py#L1-L12)、[test_api/conftest.py:21-30](file:///D:/mydemos/community-correction/tests/test_api/conftest.py#L21-L30) 均为裸 `create_engine`，未复用生产 PRAGMA。
- 现象：`test_session_allows_null_analysis_json_and_defaults_codes` 同事务插 `subjects + sessions` 能过，是因为外键关闭；手工开启后失败（M1）。
- 建议：统一 fixture 执行 `PRAGMA foreign_keys=ON`，补非法枚举、重复 `window_end`、孤儿 `subject_id` 三条负例。

**M3. 未捕获异常日志写入 `str(exc)`，可带出绝对路径（及未来含转写的 SQL 参数）**

- 位置：[errors.py:68-72](file:///D:/mydemos/community-correction/app/api/errors.py#L68-L72)、[errors.py:105-114](file:///D:/mydemos/community-correction/app/api/errors.py#L105-L114)。
- 证据：`RuntimeError("failed reading D:/storage/.../audio.wav")` 会原样写入 `api.unhandled_exception` 日志；仅 `OSError` 被置空，`DBAPIError` 会带 SQL 与 `[parameters: ...]`。
- 影响：当前无已知触发路径，属潜伏向量；违反 [api.md:162](file:///D:/mydemos/community-correction/docs/contracts/api.md#L162) 红线。
- 建议：日志只记录异常类型 + 自有错误码，或对摘要做路径/参数段清洗。

**M4. 后台写回使用模块级 `SessionLocal`，绕过依赖注入，测试不可观测且可能触碰真实库/摄像头**

- 位置：[sessions.py:63-124](file:///D:/mydemos/community-correction/app/api/routers/sessions.py#L63-L124)（[sessions.py:32](file:///D:/mydemos/community-correction/app/api/routers/sessions.py#L32) 导入，[sessions.py:76](file:///D:/mydemos/community-correction/app/api/routers/sessions.py#L76) 使用）。
- 证据：`dependency_overrides[get_db]` 指向内存库后 `POST /api/sessions`，后台任务查不到该 session，写入落回真实 DB；`GET` 仍为 `created`。
- 建议：后台任务接收可注入的 session factory（或 `app.state`），并在测试中 monkeypatch `run_capture_session`；补「成功回写 / 失败回写 / capture_busy」三条回归。

### 低风险（建议）

- **L1 `camera_resolution` 来源不一致**：[camera.py:151-159](file:///D:/mydemos/community-correction/app/capture/camera.py#L151-L159) 取 `frame.shape`，契约 [capture.md:159](file:///D:/mydemos/community-correction/docs/contracts/capture.md#L159) 写 `CAP_PROP_*`，导致 `camera_resolution_unknown` 真实路径不可达。建议契约改为「以实际帧尺寸为准，缺失时 `[0,0]`」。
