## 1. 背景与问题

社区矫正日常管理中，工作人员需要在有限频次的面谈之间判断矫正对象的情绪与心理状态变化。当前的判断依赖人工观察和主观记录，存在三个问题：

1. **观察不连续**：两次面谈之间几乎没有信息，状态变化只能靠回溯回忆。
2. **判断不可复核**：结论停留在个人印象里，没有可追溯的触发依据。
3. **缺少分级口径**：不同工作人员对"需要关注"的判断标准不一致。

本系统把一次采集（人脸 + 语音）转成结构化信号，再用一套固定的规则表给出分级结果。**分级结果唯一的出口是人工复核工单**，系统自身不产生任何处置动作。

## 2. 本轮目标与边界

### 2.1 目标

跑通**单对象纵向切片**：一个矫正对象从采集、分析、分级、建单到人工复核结案的完整链路，每一环都可运行、可观测、可校验。

### 2.2 本轮范围（In Scope）

| 环节 | 范围 |
|---|---|
| 采集 | 单次会话：抓拍单帧、人脸检测与裁剪、30 秒录音、会话目录打包 |
| 分析 | 四路管线（ASR / 语音情感 / 表情 / 心理文本），全部走 **mock Provider** |
| 一致性 | 三路情感结论比对，输出 `high` / `medium` / `low` |
| 分级 | 五色规则表：单次风险 + 7 日趋势偏移 + 合成与封顶 |
| 复核 | 非绿结果自动生成复核工单；管理端可流转、可留痕 |
| 用户端 | 知情同意页、采集引导页、结果反馈页（3 页） |
| 管理端 | 对象列表、会话记录检索、状态看板、复核队列（4 页） |
| 留痕 | 敏感字段查看、工单流转写 `audit_logs` |

### 2.3 明确非目标（Out of Scope）

- 真实模型接入（SenseVoice / PsyCoLLM 等只保留 Provider 接口，不实现）
- AI 对话页与多轮对话存储
- 多对象批量操作、跨对象聚合排名、风险榜单
- 任何形式的自动处置：限制、通报、扣分、自动升级管控等级
- 生产级鉴权（真实身份体系、单点登录）、数据加密与密钥管理
- 移动端适配、离线模式、消息推送
- 数据导出、报表打印

> 上述非目标不是"以后再说"，而是原型阶段**刻意不做**，避免验证结论被外围功能稀释。

## 3. 角色

| 角色 | 标识 | 使用端 | 核心诉求 |
|---|---|---|---|
| 社矫人员 | `subject` | 用户端 | 知道这次采集做什么、能看什么、不想采可以撤回 |
| 工作人员 | `staff` | 管理端 | 快速看到需要关注的人，且能看到判断依据 |
| 系统 | `system` | 无界面 | 按规定规则产出结果，不越权判断 |

## 4. 核心用户故事与验收标准

### US-1 采集前知情同意（P0）

> 作为社矫人员，我第一次使用时需要明确知道采集什么、做什么用、存多久、怎么撤回，同意之后才能开始采集。

**验收标准**

- [ ] 首次进入必须经过同意页，未同意不可进入采集引导页
- [ ] 同意页逐项列出：采集内容（面部图像、语音）、用途（状态信号辅助人工判断）、保存期限、撤回方式
- [ ] 人脸与语音的同意项**独立于**总协议，可分别勾选
- [ ] 撤回入口在用户端任意页面可达，撤回后不再发起新采集
- [ ] 同意/撤回行为写入 `subjects.consent_json` 与 `audit_logs`

### US-2 完成一次采集会话（P0）

> 作为社矫人员，我在引导页点击开始，按提示正视摄像头、说几句话，结束后得到明确反馈。

**验收标准**

- [ ] 摄像头与麦克风工作期间有常驻红点 + 文案提示，不做静默录制
- [ ] 采集产出目录含 `face.jpg`、`audio.wav`、`meta.json`，不含原始帧
- [ ] 未检测到人脸时返回 `capture_status=no_face`，页面给出可操作提示，不白屏
- [ ] 有效语音占比过低（低于 `CAPTURE_MIN_SPEECH_RATIO`）时返回 `capture_status=no_audio`，提示重采
- [ ] 采集过程异常一律转结构化状态，后端不返回 5xx 堆栈

### US-3 查看本次结果反馈（P0）

> 作为社矫人员，我想知道这次的状态，但不需要看到系统的分级色码。

**验收标准**

- [ ] 反馈页使用中性表述，只给行为建议与转介入口
- [ ] 响应体中**不包含** `final_color` 及任何色码字段
- [ ] 不出现"抑郁""焦虑症""人格障碍"等诊断性词汇
- [ ] 采集失败时不展示任何分析结论，只提示重采或联系工作人员

### US-4 工作人员查看对象状态（P1）

> 作为工作人员，我能在列表里看到对象的当前色码与待复核数量，并进入详情看依据。

**验收标准**

- [ ] 列表展示对象、最近分级色码、最近采集时间、待复核工单数
- [ ] 色码必须与"触发规则 + 证据摘要"同屏，禁止孤立的颜色块
- [ ] 不做跨对象排名、不做风险榜单

### US-5 复核工单流转（P0）

> 作为工作人员，我打开一条工单，看到触发规则和证据，给出人工结论并留痕。

**验收标准**

- [ ] 工单详情展示：触发规则编号、证据列表、时间窗口、建议复核方式
- [ ] 支持三种动作：确认（`confirm`）、修正（`correct`）、关闭（`close`）
- [ ] `correct` 必须填写 `conclusion_color` 与 `note`；`close` 必须填写 `note`
- [ ] 结论、操作人、时间写入数据库，刷新后仍可见
- [ ] 不存在"一键处置"或批量修改对象状态的入口

### US-6 会话记录回放（P1）

> 作为工作人员，我按对象和日期找一次历史会话，回看当时的分析结论与证据链。

**验收标准**

- [ ] 支持按对象、时间范围、色码筛选
- [ ] 详情可展开四路分析的结论与置信度
- [ ] 查看面部图与转写原文需显式点击，且写入 `audit_logs`

## 5. 功能清单（按模块）

### 5.1 采集

- 抓拍单帧（设备索引可配置）
- 人脸检测三级回退：MediaPipe → OpenCV DNN → Haar
- 人脸框外扩 25% 裁成正方形，JPEG 质量 85，长边 ≤ 640px
- 录音 16kHz / 单声道 / 16bit PCM / WAV，默认 30 秒
- 会话打包与元数据落盘

### 5.2 分析

- 四路 Provider：`asr`、`emotion`、`face`、`psych`，统一 `available()` + `analyze()`
- 单路异常降级为 `degraded`，不中断整条管线
- 汇总输出通过 `analysis.schema.json` 校验
- 一致性判定：三路一致 `high` / 两路一致 `medium` / 存在冲突或低置信 `low`

### 5.3 分级

- 单次风险规则（红 / 橙）
- 7 日趋势偏移规则（绿 / 蓝 / 黄）
- 合成：取较高者，再按一致性封顶
- 非绿必建复核工单

### 5.4 复核

- 工单列表与详情
- 三种流转动作与人工结论留痕
- 敏感字段折叠查看与查看留痕

## 6. 合规红线（不可协商）

以下四条为硬约束，任何实现与文档改动都不得突破：

1. **只存裁剪后的人脸**。原始帧不落盘、不写日志、不进异常信息。
2. **分级结果只出口到人工复核工单**。系统内不得存在任何自动处置链路。
3. **色码只在管理端显示**，且必须与证据链同屏。用户端不显示色码。
4. **无证据链的分级结果视为 bug**。每条颜色必须能定位到"哪条规则、哪个字段、哪次会话"。

## 7. 成功指标（原型阶段）

| 指标 | 目标 | 说明 |
|---|---|---|
| 端到端可跑通率 | 100% | mock Provider 下，从建会话到工单流转无人工干预 |
| 契约一致性 | 0 处冲突 | `qa-guard` 校验 `docs/contracts/` 与实现，无字段/路径不一致 |
| 规则测试覆盖 | 每规则 ≥ 3 个边界用例 | 阈值上一位、等于、下一位 |
| 证据链完整率 | 100% | 所有非绿结果均带 `rule_id` + `field_path` + `session_id` |
| 隐私冒烟 | 0 处泄露 | 日志与响应无原始帧路径、无音频 base64、转写原文不直出 |
| 采集失败可解释率 | 100% | 所有失败态有结构化 `reason` 与用户可读文案 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| mock 结论与真模型差异大 | 规则阈值标定失真 | 阈值集中在 `app/grading/config.py`，全部标 `TODO: 待标定`，不当作临床依据 |
| 摄像头在终端机上不可用 | 采集链路无法验证 | 采集层支持注入假数据与固定图片，测试不依赖真实设备 |
| 一致性冲突被误读为风险升级 | 误判风险 | 一致性只下调置信度并转人工，禁止改 `risk_level` |
| 敏感数据被前端缓存 | 隐私泄露 | 禁止写入 localStorage / IndexedDB，仅内存态 |
| 工作人员依赖色码跳过读证据 | 判断退化 | 色码与证据链强制同屏，详情页不提供只看颜色的折叠态 |
